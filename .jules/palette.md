## 2024-06-16 - Keyboard Accessibility for Radix UI Triggers
**Learning:** When using custom elements like `<button>` inside Radix UI components with `asChild` (such as `PopoverTrigger` or `DialogTrigger`), the default keyboard focus outline is often lost or obscured by reset styles. Furthermore, non-semantic interactive elements like `<div onClick={...}>` completely lack native keyboard focus and screen reader semantics.
**Action:** Always manually apply Tailwind focus utilities (e.g., `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2`) and proper border-radius to custom trigger elements. Convert all clickable `<div>` elements to semantic `<button type="button">` elements with descriptive `aria-label`s and focus states.
